21. ★★ **改 `pdd_flow.js` 的三条铁律**（2026-09-29 我亲手删掉 35KB 代码的事故）：
    **(1) 动手前先备份** —— 这次全靠 `_backup/pdd_flow.js.<时间戳>.bak` 才找回 20 个函数，没备份就是不可逆。
    **(2) 字符串切片/`replace` 打补丁前必须断言 `start < end`** —— 顺序反了会把中间所有代码一并替换掉
    （我那次删掉 20 个函数，`require` 都解析不了）。
    **(3) 抠函数体要先跳过参数表的括号再找函数体 `{`** —— JS 参数里可有对象解构
    （`function clearZone(page, keyword, total, { max = 60 } = {})` 的第一个 `{` 就是解构，
    从那儿配对会把函数截断在参数表）。
    **恢复后审计三件套**：`node --check` → `require` 成功 → 导出逐个 `typeof === 'function'` 点名核对。
    ⚠️ 顶层 `const` 也在被删之列（我漏了 `ZONE_KEYS`，因为「缺函数」审计只看 function，
    跑起来才报 `ZONE_KEYS is not defined`）——审计要**同时扫顶层常量**。

22. ★ **新版流程提速三条**（逐项实测：总时长 399.8s → 286.0s，−28%）：
    **(1) 第一步 `setInputFiles` 之后不要等上传，立刻去填标题**（上传是服务端并行的，等计数器纯串行浪费；
    只有「手动选择商品分类」入口没出现时才回头等）→ 类目第一步 46.5s→**26.4s**。
    **(2) 规格填写三处去白费**：空槽位跳过 `Ctrl+A`/`Backspace`；逐字 `type` 换 `keyboard.insertText`
    （一次性插入、**仍触发真实 input 事件**，≠ 不可靠的 `evaluate` 写 value）；Tab 后 700→**400ms**
    → 规格表 49.3s→**23.5s**。
    **(3) 逐行循环里禁用 `innerText`，用 `textContent`**（`innerText` 强制重排，一次全表扫描约 900 行次调用）
    → 填值+校验 80.5s→**43.3s**。
    **(4) 上传计数器有两套文案**：表单区 `已上传N/M张`、**新版第一步 `上传图片 (N/M)`**（无「已上传」无「张」）。
    `waitForUploads` 必须都认 + 「缩略图数 ≥ N」兜底，否则会白耗满超时（我曾因此把它从 46.5s 拖到 82.7s）。
    当前最大头是**预览图（139.7s，占总时 49%）**。
